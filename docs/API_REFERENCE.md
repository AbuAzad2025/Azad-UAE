Generated by `scripts/lint/generate_api_reference.py` from the live Flask
`url_map`. Do not edit by hand: `scripts/lint/check_api_docs.py` fails when
this file drifts from the code, so a hand-written endpoint that does not
exist cannot survive a CI run.

- **Endpoints documented:** 773
- **Blueprints:** 54
- **Source of truth:** `app.url_map` at runtime, not a hand-maintained list

This document previously described an outbound webhook subscribe endpoint,
`X-Webhook-Signature` headers, per-plan rate limits and `POST /api/sales`.
None of those exist in this codebase. The file was deleted rather than
patched, and this generated replacement was written to stop the same class
of drift returning.

## Response envelope

Responses come from `utils/api_response.py`, not from ad-hoc `jsonify`.

```json
{"success": true,  "data": {}, "message": null, "errors": null, "meta": null}
{"success": false, "data": null, "message": "…", "errors": [], "meta": null}
```

Helpers:

- `success_response(data: Any = None, message: str | None = None, meta: dict | None = None, status_code: int = 200,)`
- `error_response(message: str, errors: list | None = None, status_code: int = 400, meta: dict | None = None,)`
- `paginated_response(items: list, page: int, per_page: int, total: int, message: str | None = None, meta: dict | None = None,)`

Pagination nests under `meta.pagination` with keys `page`, `per_page`,
`total`, `pages`, `has_next`, `has_prev` — note `pages`, not `total_pages`,
and not at the top level of `meta`.

Two responses do not use this envelope, by design and by legacy:
`@api_key_required` returns `{"ok": false, "error": …}` with 401/403, and
the global error handlers in `app/handlers.py` return `{"success": false,
"error": …}`.

## Guards

Access control is enforced in two places, and both are captured below.

- **Per-route decorators** — `@login_required`, `@permission_required`,
  `@owner_required`, `@api_key_required`.
- **Blueprint `before_request` hooks** — five blueprints guard their whole
  surface this way, so a decorator-only audit wrongly reports them open:

  - `api_docs` → authenticated_when_production
  - `owner_admin` → ip_allowlist
  - `payment_vault` → owner, authenticated
  - `pos` → feature_flag:pos_enabled
  - `reports` → tenant_scope
